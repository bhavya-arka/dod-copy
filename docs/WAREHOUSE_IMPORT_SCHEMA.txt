                    INVENTORY IMPORT DATA SCHEMA
================================================================================

Document Version: 1.0
Last Updated: January 2026
System: ARKA Cargo Operations - Warehouse Management Module

This document describes the complete schema for warehouse inventory data import.
Data can be imported via CSV, XLSX, XLS, or PDF files.

================================================================================
                           SUPPORTED FILE FORMATS
================================================================================

1. CSV (Comma-Separated Values)
   - Standard CSV with header row
   - UTF-8 encoding recommended
   - Comma delimiter (configurable)

2. XLSX/XLS (Microsoft Excel)
   - First sheet is parsed by default
   - First row must contain column headers
   - Supports both .xlsx and legacy .xls formats

3. PDF (Portable Document Format)
   - Tabular data extracted from PDF tables
   - Best results with structured, grid-based PDFs
   - Complex layouts may require manual review

================================================================================
                         DATA TYPE SPECIFICATIONS
================================================================================

TEXT
----
- Variable-length character string
- No maximum length enforced
- UTF-8 encoding supported
- Leading/trailing whitespace trimmed on import

INTEGER
-------
- Whole numbers only
- Range: -2,147,483,648 to 2,147,483,647
- Non-numeric values will fail validation

DECIMAL (NUMERIC)
-----------------
- Supports decimal precision
- unit_price/receipt_price: 14 digits total, 2 decimal places
- weight_lbs: 12 digits total, 2 decimal places
- Currency symbols ($) are stripped during import
- Commas in numbers are handled automatically

TIMESTAMP
---------
- ISO 8601 format preferred: YYYY-MM-DDTHH:MM:SSZ
- Also accepts: MM/DD/YYYY, DD-MMM-YYYY, YYYY-MM-DD
- Stored in UTC timezone

JSONB
-----
- Binary JSON format (internal use)
- Preserves original import row data

================================================================================
                         GOVERNMENT COMPLIANCE
================================================================================

NATIONAL STOCK NUMBER (NSN) FORMAT
----------------------------------
Full format: XXXX-XX-XXX-XXXX (13 characters with dashes)

Components:
- FSC (Federal Supply Classification): First 4 digits
- NIIN (National Item Identification Number): Last 9 digits

Example: 5340-01-234-5678
         ^^^^              = FSC: 5340 (Hardware and Abrasives)
              ^^^^^^^^^    = NIIN: 012345678

The system automatically:
- Validates NSN format
- Extracts FSC and NIIN components
- Cross-references with Federal Catalog data (when available)

CAGE CODE FORMAT
----------------
5-character alphanumeric code assigned by DLA.
Example: 1ABC2, 5F654

Identifies the manufacturer/supplier for government contracts.

CONDITION CODES
---------------
Standard DoD condition codes supported:

Code | Description
-----|----------------------------------------
A    | Serviceable (new or like-new)
B    | Serviceable (good condition)
C    | Serviceable (fair condition)
D    | Serviceable (meets minimum standards)
E    | Unserviceable (repairable)
F    | Unserviceable (condemned)
G    | Unserviceable (incomplete)
H    | Unserviceable (scrap)

================================================================================
                         IMPORT VALIDATION RULES
================================================================================

REQUIRED FIELDS
---------------
1. description - Must be non-empty string
2. quantity - Must be valid integer (defaults to 0 if missing)

AUTOMATIC TRANSFORMATIONS
-------------------------
1. Currency symbols removed from price fields
2. Commas removed from numeric values
3. Date formats normalized
4. Leading/trailing whitespace trimmed
5. Empty strings converted to NULL

VALIDATION WARNINGS (Non-blocking)
----------------------------------
- Missing NSN or incomplete format
- Quantity = 0 (may indicate data issue)
- Missing location data
- Expired items (exp_date in past)
- High-value items without serial numbers

VALIDATION ERRORS (Import Blocked)
----------------------------------
- Missing required description field
- Invalid numeric format in quantity/price fields
- Duplicate requisition_no within same import (configurable)

================================================================================
                         OPTIMIZATION DATA USAGE
================================================================================

The following fields are used by the optimization algorithms:

CARDSTACK ALGORITHM
-------------------
- ship_class: Groups items by ship class for consolidation
- program_code: Secondary grouping criteria
- location: Current rack location for stacking analysis

SIZE STANDARDIZATION
--------------------
- program_code: Groups items by program for zone optimization
- location: Current location for movement recommendations

VALUE DENSITY
-------------
- unit_price: Determines high-value items
- quantity: Total value calculation (unit_price x quantity)
- location: Accessibility scoring for relocations

BIN-PACKING
-----------
- material_disposition: Groups items by disposal/transfer status
- quantity: Pallet capacity calculations
- weight_lbs: Weight constraint validation
