## 📌 **App Specification — Military Organization & Role-Based Permissions**

### **1. Project Overview**

The app will support user accounts *tied to specific military organizations* (PACAF, DLA, MSC, TRANSCOM), with **role-based permissions** and **superadmin control**.

---

### **2. Key Roles & Permissions**

| Role             | Scope                        | Capabilities                                                                                  |
| ---------------- | ---------------------------- | --------------------------------------------------------------------------------------------- |
| **Superadmin**   | Global                       | Full system access across all branches; create/edit/delete admins and users; override actions |
| **Branch Admin** | PACAF / DLA / MSC / TRANSCOM | Approve members, manage accounts within branch, generate access codes, view alerts            |
| **User**         | Assigned branch              | Standard access based on branch and privileges issued by admin                                |

---

### **3. High-Level Features**

**A. Authentication & Authorization**

* JWT / OAuth2 based token system
* Role-based permission enforcement at route/middleware level
* Superadmin token bypasses branch restrictions where appropriate

**B. Organization Management**
✔ Store user organizations: PACAF, DLA, MSC, TRANSCOM
✔ Tag users with *organization + role*
✔ Admin dashboard to manage branch info

**C. Account Management**

* Automatic *Department Access Code* (DAC) generation
* Admins can:

  * Create branch admins and users
  * Reset or manage passwords
  * Approve/deny user signups
* Superadmin can manage *all* accounts across all branches

**D. Alerts & Notifications**

* Unapproved signup alerts on admin dashboard
* Email notifications for actions pending admin approval

**E. Logs & Audit**

* Track all actions tied to user + branch
* Superadmin can audit any branch

Organization {

#### **AccessCodes Table**

```sql
AccessCode {
  id (PK)
  code (string)
  organization_id (FK)
  created_by_user_id (FK)
  expires_at
  is_used (boolean)
  created_at
}
```

---

### **5. Backend Routing (RESTful)**

Routes are guarded by **permission middleware**.

**Public**

```
POST /auth/signup    → create pending user with AccessCode
POST /auth/login     → returns token
GET  /status         → health check
```

**Superadmin Only**

```
POST /orgs           → create org (optional)
POST /users          → create any user
PUT  /users/:id      → update any user
DELETE /users/:id    → delete user
```

**Branch Admin**

```
GET  /users          → list users by branch
POST /accesscodes    → generate new DAC
PUT  /users/:id      → update user (within branch)
POST /users/approve  → approve pending signup
```

**Authenticated Users**

```
GET /profile
PUT /profile
```

---

### **6. Permissions Flow**

1. **User signs up** → must enter valid *Department Access Code* → stored as pending
2. **Branch Admin alerted** → approves user → user becomes active
3. **Superadmin** → can approve any pending signup
4. **Token middleware** → validates user + permissions before proceeding
